# 1: Python Foundations

## 1.1. Python Installation

### Option A: **Using system Python (default OS Python)**

- On **Windows**: Install from [python.org](https://www.python.org/downloads/)

  - During installation: "Add Python to PATH"

- On **Linux/macOS**:

  - macOS: comes with system Python (`/usr/bin/python3`)
  - Linux: install via package manager (e.g. `sudo apt install python3`)

But managing multiple versions becomes messy. Instead, use `pyenv`.

### Option B: **Using `pyenv` (recommended)**

Lets you manage multiple Python versions easily.

#### Install pyenv

**macOS/Linux (bash/zsh)**:

```bash
curl https://pyenv.run | bash
```

Then add to your `~/.bashrc`, `~/.zshrc`, or `~/.bash_profile`:

```bash
export PATH="$HOME/.pyenv/bin:$PATH"
eval "$(pyenv init --path)"
eval "$(pyenv virtualenv-init -)"
```

**Windows**: Use [`pyenv-win`](https://github.com/pyenv-win/pyenv-win)

```powershell
git clone https://github.com/pyenv-win/pyenv-win.git "$HOME/.pyenv"
setx PATH "$HOME\.pyenv\pyenv-win\bin;$HOME\.pyenv\pyenv-win\shims;%PATH%"
```

#### Install Python using `pyenv`:

```bash
pyenv install 3.12.3
pyenv global 3.12.3
```

Verify:

```bash
python --version
```

## 1.2. Virtual Environments

A **virtual environment** is an isolated Python environment that has its own Python binary and packages, separate from your system Python. It helps avoid **dependency conflicts**.

### Tools to Create Virtual Environments

| Tool         | Description                             | OS Support            | Notes                           |
| ------------ | --------------------------------------- | --------------------- | ------------------------------- |
| `venv`       | Standard module (Python 3.3+)           | Windows, Linux, macOS | Most common and recommended     |
| `virtualenv` | Third-party tool (older Python support) | Windows, Linux, macOS | Needed if using Python <3.3     |
| `conda`      | From Anaconda distribution              | Cross-platform        | Used in data science workflows  |
| `pipenv`     | Combines pip + virtualenv + Pipfile     | Cross-platform        | Good for beginners/project mgmt |
| `poetry`     | Modern dependency + packaging tool      | Cross-platform        | Recommended for modern apps     |

## Recommended Way (for most use cases)

### Use `venv` (built-in) unless you have special needs

## Step-by-Step: How to Use `venv`

### 1. Windows (CMD or PowerShell)

```bash
# Create virtual environment in folder "venv"
python -m venv venv

# Activate it (CMD)
venv\Scripts\activate.bat

# Or, in PowerShell
venv\Scripts\Activate.ps1

# Deactivate
deactivate
```

### 2. Linux / macOS (bash/zsh)

```bash
# Create virtual environment
python3 -m venv venv

# Activate
source venv/bin/activate

# Deactivate
deactivate
```

### 3. Using `virtualenv` (if using Python < 3.3)

```bash
pip install virtualenv
virtualenv myenv
source myenv/bin/activate     # Linux/macOS
myenv\Scripts\activate.bat    # Windows
```

### 4. Using `pipenv` (Optional modern workflow)

```bash
pip install pipenv
pipenv shell                  # auto-creates a venv
pipenv install requests       # installs in that venv
```

### 5. Using `poetry` (Advanced / Production use)

```bash
pip install poetry
poetry init                   # setup pyproject.toml
poetry shell                  # starts venv
poetry add requests           # adds dependency
```

## Best Practices

- Use one virtual environment per project
- Don’t commit the `venv` folder to Git
- Store dependencies using `requirements.txt` or `pyproject.toml`

## Example: Save and Install Dependencies

```bash
# Save current packages
pip freeze > requirements.txt

# Install from file
pip install -r requirements.txt
```

## Check Virtual Env Is Active

```bash
# In terminal
which python        # Linux/macOS
where python        # Windows

# Output should point to your venv
```
